# 答复 markdown 强制结构

boss-recall 不写自由散文，所有答复必须按下面 4 段式骨架。**所有引用必须给 ID 或文件:行号**。

## 骨架（按出现顺序）

```markdown
## "{原问题}"

### 📌 直接答复
{1–3 句话直接回答。可以含核心数字、当前状态、最近时间锚点。}

### 🕐 时间线 / 会议轨迹 / 决策链
{结构化展示，不要散文。}
- **YYYY-MM-DD**（{会议主标题}）：{发生了什么}
- …

### 📋 当前状态
- 🎯 **关联决策**：{D-XXX} {决策内容} —— **状态：active/superseded/done/dropped**
- 🔄 **未闭环待办**：{A-XXX} {待办标题} —— **截止 YYYY-MM-DD，状态：open/in-progress/blocked**
- 👥 **核心相关人**：{人 1}、{人 2}

### 🔗 引用源
- meeting-index.md: {行号或日期范围}
- decision-ledger.md: {D-XXX}, {D-YYY}
- people-graph.md: {姓名}「历史关键观点」第 X 条
- topic-threads.md: ## {主题}
- action-items.md: {A-XXX}
```

## 4 段强制规则

### 📌 直接答复（必填）
- 1–3 句话
- 必须包含一个**可验证的数字或日期**
- 不能含"也许 / 大概 / 可能"等不确定词——L3 里有就有，没有就说没有

### 🕐 时间线（按查询类型变体）
- 按人/按主题查 → 用「时间线」标题
- 按时间查 → 用「会议清单」+ 表格
- 按决策查 → 用「决策链」+ 推翻关系标注
- 按待办查 → 用「待办清单」+ 表格 + 状态列

### 📋 当前状态（必填，即使为空也写）
- 即使没有相关决策/待办也要明确写"无"——避免老板以为漏了
- 状态字段必须如实抄 L3 文件原值

### 🔗 引用源（必填）
- 每条信息至少有一个 L3 文件来源
- 链接格式：`{文件名}: {ID 或行号}` —— 让老板可以直接打开 markdown 文件验证

## 不要做的事

❌ **不要软化语调**：不写"我推测"、"可能"——L3 里有就引用，没有就说"L3 中无相关记录"
❌ **不要滑回 boss-meeting 的犀利视角**：boss-recall 是查询员，不点盲点不评判
❌ **不要把多条信息揉成段散文**：永远用 bullet / 表格 / 编号
❌ **不要省略 ID**：决策必带 D-XXX，待办必带 A-XXX
❌ **不要主动展示 dropped/archived 内容**：除非老板明确问"包括取消的"

## 抽象查询 vs 极模糊查询的处理

### 抽象查询（默认：智能拼装）

老板问的关键词在 L3 里**没有完全同名的条目**，但**议题指向明确**。例如：
- "我们决定怎么用强人？" —— L3 里没有题为"用强人"的决策，但有 ≥3 条决策围绕这个母题
- "出海这事怎么决定的？" —— 没有"出海决议"标题，但有相关主题 + 多条决策

**默认做法：智能拼装**。

- 把所有相关决策 / 待办 / 主题按议题归类（即使条目名不含原查询关键词）
- 答复正文照常给出完整 4 段式答案
- **末尾加一行可选澄清**：

```markdown
> 💬 如果你问的不是这个，请指明候选：(候选 A) / (候选 B) / 重新描述
```

候选从 topic-threads.md 中按"最近活跃"排序的前 3–5 个 active 主题给出。

智能拼装的触发条件：
- 至少能拼出 ≥ 3 条相关决策 / 待办 / 主题
- 且这些条目能形成有内聚的逻辑链（不是堆砌无关条目）

### 极模糊查询（先澄清）

老板问得**完全无法定位**，例如：
- "那个事进展怎么样" —— 没有任何上下文锁定哪件事
- "上次说的那个" —— 没有任何关键词

**做法：用当前 runtime 的提问机制先澄清，不直接答**（Claude Code: AskUserQuestion；Hermes: 直接 markdown 输出候选；其他 LLM: 按 wrapper）：

```markdown
你说的"那个事"具体指什么？候选：
- "{主题 A}"（最近活跃 YYYY-MM-DD）
- "{主题 B}"（最近活跃 YYYY-MM-DD）
- "{主题 C}"（最近活跃 YYYY-MM-DD）
- 其他（请补充关键词）
```

候选从 topic-threads.md 中按"最近活跃"排序的前 5 个 active 主题给出。

### 判定边界

| 查询特征 | 处理 |
|---------|------|
| 含明确关键词 + L3 有同名条目 | 直接答（标准流程）|
| 含明确关键词 + L3 无同名条目，但能拼 ≥ 3 条相关 | **智能拼装** + 末尾可选澄清 |
| 关键词极抽象 / 全是代词 / 拼不出 3 条相关 | **runtime 提问机制先澄清** |

## 空 L3 处理

如果检索结果完全为空：

```markdown
## "{原问题}"

### 📌 直接答复
L3 中无相关记录。可能的原因：
- 该主题/人物从未在跑过的会议里出现
- 用户使用了与图谱不同的称呼（请确认拼写或别名）
- L3 是新初始化的，还没攒数据

### 🛠 建议
- 用 `boss-meeting` 跑一次会议把这个议题入库
- 或手动检查 `~/.claude/boss/people-graph.md` / `topic-threads.md` 确认确实没有
```
