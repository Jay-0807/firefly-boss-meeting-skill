# 6 类查询范式 + Few-shot

## 1. 按人查

### 触发信号
- 具名：「大富说过什么」「跟马磊聊的事」
- 代词 + 上下文：「他上次提到的方案」「这位嘉宾分享了什么」
- 角色：「客服主管那边」（依赖 people-graph 的 `角色` 字段映射）

### 检索流程
1. 在 `people-graph.md` 全文搜索姓名/别名 → 锁定条目
2. 取出该人的「历史关键观点」时间序列
3. 用每条观点的 YYYY-MM-DD 反查 `meeting-index.md` 拿对应会议主标题
4. 用同日期 + 该人姓名反查 `decision-ledger.md` / `action-items.md` 的「关联人物」字段
5. 组装时间线

### 模板答复

```markdown
## "{原问题}"

### 📌 直接答复
{老板姓名} 在 L3 中共出现 N 次会议，最近一次是 YYYY-MM-DD（{会议主标题}）。当前可调取的核心观点共 M 条。

### 🕐 时间线
- **YYYY-MM-DD**（{会议主标题}）：{该人在此次会议提出的核心观点}
- …

### 📋 当前状态（与该人相关）
- 🎯 **active 决策**：D-XXX (该人为责任主体或关联人物)
- 🔄 **未闭环待办**：A-XXX
- 👤 **画像摘要**：{从 people-graph 取 ≤ 200 字画像}

### 🔗 引用源
- people-graph.md: ## {姓名}
- meeting-index.md: 行 X / Y / Z
```

## 2. 按主题查

### 触发信号
- 项目代号：「X-1 那个事」「上市这块」
- 业务方向词：「AI 客服」「供应链优化」「品牌建设」
- 反问式：「{主题} 进展怎么样」「{主题} 还在推吗」

### 检索流程
1. 在 `topic-threads.md` 全文搜索主题名（含 ≥ 50% 字符重叠）→ 锁定主题
2. 取出该主题的「会议轨迹」「关键决策锚」「未闭环待办」三条线
3. 顺着这三条线分别去 meeting-index / decision-ledger / action-items 取详情
4. 组装"主题画像 + 时间演进 + 当前节点"

### 模板答复

```markdown
## "{原问题}"

### 📌 直接答复
{主题名} 当前状态 active / dormant / archived。
最近活跃 YYYY-MM-DD。当前路径：{从 topic-threads "当前路径" 字段直接复制}。

### 🕐 会议轨迹
{从 topic-threads 取「会议轨迹」全部条目，按时间倒序}

### 🎯 关键决策（按时间倒序）
- **D-XXX**（YYYY-MM-DD）{决策内容} —— **状态：active**
- **D-XXX**（YYYY-MM-DD）{决策内容} —— **状态：superseded**（被 D-YYY 替代）
- …

### 🔄 未闭环待办
- **A-XXX**：{动作} | 负责人 {X} | 截止 {Y} | **状态：open**
- …

### 👥 核心相关人
{从 topic-threads 「核心相关人」取，附最近一次观点摘要}
```

## 3. 按时间查

### 触发信号
- 相对时间：「上周」「上个月」「三周前那场」
- 绝对时间：「四月份」「2026-04-21 那次」
- 时段限定：「最近 5 场会议」「年初到现在」

### 检索流程
1. 解析时间范围（→ `time_window`）
2. 在 `meeting-index.md` 按日期列筛选命中行
3. 命中行的"主标题"反查 decision-ledger / action-items / topic-threads
4. 输出该时段会议列表 + 各场关键决策摘要

### 模板答复

```markdown
## "{原问题}"

### 📌 直接答复
{时间窗} 共开过 N 场会议，产生 M 条决策，K 条待办。

### 🕐 会议清单（按时间倒序）
| 日期 | 主标题 | 类型 | 主要参与人 | 决策数 | 待办数 |
|-----|-------|------|----------|-------|-------|
| YYYY-MM-DD | {主标题} | {类型} | … | N | M |
| …

### 🎯 时段内关键决策
- **D-XXX**（YYYY-MM-DD）{决策内容} —— **active**
- …

### 🔄 时段内未闭环待办
- **A-XXX**：{动作} | 负责人 {X} | 当前 **open**
- …

### 📊 主题分布（按出现频次）
- {主题 A}: 出现在 X 场会议
- {主题 B}: Y 场
```

## 4. 按决策查

### 触发信号
- 直接：「我们决定了什么」「关于 X 的决议是什么」
- 反问式：「为什么决定走这条路」「之前怎么定的」
- 推翻溯源：「之前不是说 A 吗，怎么改 B 了」

### 检索流程
1. 在 `decision-ledger.md` 按关键词（决策内容、关联主题、关联人物）全文搜索
2. 命中条目的状态变更历史：
   - 如果 active → 直接展示
   - 如果 superseded → **必须**找出推翻它的新决策（看变更历史里 `被 D-XXX 替代` 的引用）
   - 如果 done → 展示 + 标记完成日期
3. 顺着关联主题 / 关联人物补充上下文

### 模板答复

```markdown
## "{原问题}"

### 📌 直接答复
找到 N 条相关决策。最新有效决策是 **D-XXX（active）**：{决策内容}。

### 🎯 决策链（按时间正序，展示推翻关系）
1. **D-XXX**（YYYY-MM-DD）{决策内容}
   - 状态：**superseded** —— 被 D-YYY 替代（YYYY-MM-DD）
   - 原因：{从状态变更历史拿}
2. **D-YYY**（YYYY-MM-DD）{决策内容}
   - 状态：**active**
3. …

### 🔗 关联上下文
- 关联主题：{主题名}
- 关联人物：{人 1}、{人 2}
- 关联待办：A-XXX / A-YYY

### ⚠ 锁死性反复警告（如适用）
{若同一议题有 ≥ 3 次推翻，给出明确警告}
```

## 5. 按待办查

### 触发信号
- 完成情况：「做完没」「闭环了吗」
- 列表：「还有哪些事没做」「我的 todo」
- 逾期：「过期的任务」「卡住的事」

### 检索流程
1. 在 `action-items.md` 按关键词 / 负责人筛选
2. 状态过滤：
   - 默认显示 open / in-progress / blocked
   - 老板明确问历史时也显示 done / dropped
3. 按截止日期排序，逾期的标红
4. **逾期下游链反查**（重要）：发现任意逾期待办时，沿 `关联决策` 字段反查该决策状态——若为 active 但其落地依赖该待办，则标注"下游连锁影响"；若该决策又是某次会议的核心交付，再反查 meeting-index 和其他相关待办。这条链让"一条逾期"暴露出整片连锁风险

### 模板答复

```markdown
## "{原问题}"

### 📌 直接答复
共找到 N 条相关待办。{open: X, in-progress: Y, blocked: Z, done: W}。{若有逾期，明确写"逾期 N 天，状态：xxx"}

### 🔄 待办清单（按截止日期排序，逾期⚠在前）

| ID | 标题 | 负责人 | 截止 | 状态 | 关联决策 |
|----|------|-------|------|------|---------|
| A-XXX | {标题} | {人} | YYYY-MM-DD ⚠ 逾期 N 天 | **blocked** | D-XXX |
| A-YYY | {标题} | {人} | YYYY-MM-DD | **open** | D-YYY |
| …

### 🚨 风险信号
- 逾期未闭环：N 条
- 同主题反复 dropped：{若有}

### 🔗 下游连锁影响（逾期触发时必填）
- **D-XXX**（active）：该决策的落地依赖逾期待办 A-XXX。当前 A-XXX 未交付意味着...
- **A-YYY**（open）：该待办与逾期项同属一条议题链，截止日 YYYY-MM-DD 也未推进
- **{相关会议}**（meeting-index）：该会议的核心交付物即为逾期项，会议本身可能已延期或被迫仓促进行
```

**逾期下游链规则**：
- 任一逾期待办触发，都要沿 `关联决策` → 该决策的"时间窗"约束 → 同一决策下的其他待办 → meeting-index 中的相关会议 反查
- 输出连锁影响 ≤ 5 条，按因果距离排序
- 不要硬凑——查不到下游就直接写"无下游连锁"

## 6. 按模式查（图谱回声扫描）

### 触发信号
- 元问题：「我自己有没有反复犯同一个盲点」
- 趋势：「最近这种问题是不是越来越多」
- 周期：「上次也是这样吗」

### 检索流程
1. **跨人物模式扫描**：people-graph 中老板自己（boss_name 标签）的「历史关键观点」找重复语义片段
2. **决策链反复扫描**：decision-ledger 找同一关联主题下的 superseded 链
3. **待办反复扫描**：action-items 找同主题反复 dropped 或反复 reopened 的痕迹
4. 综合出"模式诊断"

### 模板答复

```markdown
## "{原问题}"

### 📌 模式诊断
检测到 N 个潜在的锁死性反复模式：

### 🔁 模式 1：{一句话描述}
- 出现频次：N 次（YYYY-MM-DD ~ YYYY-MM-DD）
- 触发场景：每次涉及 {主题/类型} 时
- 证据链：
  - YYYY-MM-DD（{会议}）{该次表现}
  - YYYY-MM-DD（{会议}）{再次表现}
- **诊断**：{1–2 句核心判断}

### 🔁 模式 2：…

### ⚠ 严重度评估
{1（一次性偶然）/ 2（值得警惕）/ 3（锁死性下行——必须主动干预）}
```

## 通用约束

1. 找不到 → 明说"L3 中无此记录"，不胡编
2. 时间不一致 → 引用 meeting-index 为准
3. 状态有歧义 → 直接展示原始 status 字段，让老板判断
4. 跨多人/多主题 → **结构化展示**，不要把多条信息揉成段散文
