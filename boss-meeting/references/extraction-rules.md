# 抽取规则：决策、盲点、待办、名字归一

## 1. 决策提取规则

**只把以下三类内容标为「决策」**，其他都是「讨论要点」（进纪要的描述部分，不进决策长图的「外部决策结论」section）。

### 类型 A：承诺性话术
转写中出现以下措辞之一：
- 「我们决定…」
- 「接下来要…」
- 「计划在 X 之前完成…」
- 「下周开始 / 下个月起 / 明天就…」
- 「这事儿就这么定了 / 拍板…」

### 类型 B：明确责任 + 时间
即使没有承诺词，但同时出现：
- **责任人姓名**（具体到人，不是「团队」）
- **时间锚点**（具体日期 / 时间窗，不是「尽快」「以后」）

### 类型 C：会议明确收敛后的结论
讨论中出现强烈分歧 → 经过反复辩论 → 一方在结尾**明确接受**对方观点。这种收敛点是决策。

判定信号：
- 「行，那就按你说的来」
- 「OK，听你的」
- 「你说得对，我之前想错了」

### 反例（不要伪装成决策）

❌ 「我觉得我们以后可能会做 X」（动词「觉得」+「可能」+「以后」 → 讨论，不是决策）
❌ 「这个方向挺有意思的」（评价，不是决策）
❌ 「等 {某人} 回话再说」（被阻塞，没收敛）

## 2. 盲点识别启发式

决策长图「犀利视角」section 必须找出 2–3 个老板自己没看见的问题。**用以下启发式扫描转写**：

### 启发式 1：自我合理化
老板的发言中出现这些模式：
- 「我觉得不需要…」 + 后面没给充分理由
- 「反正大家都…」（用群体行为合理化个人决策）
- 「这种东西其实没那么…」（轻视一个被旁人多次提到的问题）
- 「我已经想过了，不用再讨论」（拒绝对抗）

→ 这通常对应一个真实存在但被老板主观过滤掉的风险。

### 启发式 2：过度乐观
老板用绝对化措辞 + 缺执行细节：
- 「这事一定能…」
- 「100% 可以做到」
- 「肯定会成」

→ 检查转写中有没有别人提出过技术 / 资源 / 时间上的具体障碍。如果有，且老板没正面回应，就是盲点。

### 启发式 3：情绪反弹
转写中出现：
- 别人提出问题 → 老板立即用反问句回击（「那你说怎么办？」）
- 别人提出问题 → 老板转移话题
- 别人提出问题 → 老板用「我们之前讨论过了」搪塞

→ 这通常是「他知道这是问题，但不想承认」，作为 AI 外脑必须点出来。

### 启发式 4：图谱回声陷阱
对比人物图谱中老板（或主要发言人）的「历史关键观点」：
- 如果老板 X 周前已经识别过的某个原则，本次会议讨论时 **没有应用** → 严重盲点
- 如果别人 X 周前已经提醒过的风险，本次会议**重复出现** → 锁死性下行

这是图谱回声的核心价值——**单看一场会议看不出"反复犯同一个错"**，只有跨会议视图才能识别。

## 3. 待办抽取规则

**三要素必须凑齐**：负责人 + 处理时间 + 动作。

### 抽取流程

1. 扫描转写中所有动作性句子（动词开头 / 「让 X 做 Y」/ 「X 这边 …」）
2. 对每个动作，回填三要素：
   - **负责人**：从上下文找最近的具名引用
   - **处理时间**：往前后扫 10 行找时间锚点
   - **动作**：动词短语 + 必要的判定标准

### 负责人写法

按下面优先级取一种：

1. **具名**（首选）：`负责人：{某人}`
2. **角色注释占位**（归一不确定时允许）：`负责人：发言人 1（{角色}）`
3. **多人并列**：`负责人：{某人 A} & {某人 B}`
4. **占位**：`负责人：(待补)` —— 必须在动作里追加「老板需要确定责任人」

### 缺要素时的处理

| 缺什么 | 怎么标 |
|--------|--------|
| 缺负责人 | `负责人：(待补)` 并在动作里加一句「老板需要确定责任人」 |
| 缺处理时间 | `处理时间：(待补)` 并在动作里加一句「待 X 回话后定时间」 |
| 缺动作描述细节 | 不要拼凑，**就直接简短描述 + 标 `(细节待补)`** |

**不允许**编造细节凑数。

## 4. 名字归一规则

### 归一优先级

1. **图谱别名命中**：转写中的标签 == 图谱中某人的「别名」 → 直接归一（高置信）
2. **图谱规范姓名命中**：转写中标签 == 图谱中某人的「规范姓名」 → 直接归一
3. **同次会议上下文映射**：
   - 转写中出现 `发言人2`，但同段后文有 `{老板} 对 {某人} 说...` → 把 `发言人2` 映射到 `{某人}`
   - 自称命中：`发言人3` 的发言中出现「我是 X」 → 映射到 X
4. **同音字 / 错别字**：
   - 转写常把同一人写成多个写法（同音异字 / 拼音回译）→ 归一前先在图谱「别名」字段查
   - 如果同音字在图谱里没记录，**问用户**而非自动归一

### 不归一的情况

- 占位标签（`发言人N`）找不到任何映射 → **进 Step 4.4 batch 询问列表**（不要逐个问）
- 同次会议中出现两个相似但不确定是否同人的标签（如 `{全名}` 和 `{名}`）→ **默认合并**，但在末尾备注让用户复核
- 跨会议出现新名字 + 在图谱中找到角色匹配但姓名不一致 → **不要自动合并**，进 batch 询问列表

### Batch 归一询问表（Step 4.4 用）

把所有未达 0.95 置信度的发言人**一次性**做成一个表格，让老板**勾选式回复**——**不要每个发言人单独发起一次问**。

表格列：

| 转写标签 | 候选 1（含命中依据 + 置信度） | 候选 2 | 候选 3 | 默认建议 |
|---------|---------------------------|-------|-------|---------|
| 发言人 2 | 西鸣（图谱别名命中 0.85）| [新人物] | [忽略] | 西鸣 |
| 发言人 3 | 文轩 | 文勋（拼音同音）| [新人物] | 文轩 |
| 师姐    | [题目漏列参会人——请补姓名] | 越影戏称展沅 | [忽略] | [题目漏列参会人] |

填表规则：

- **候选 1** 永远是当前最高置信度的归一目标
- **`[新人物]`** 表示老板要简述身份，触发新增 people-graph 条目
- **`[忽略]`** 表示该发言人是无关旁白（背景音、客服回应等），不入图谱也不入纪要
- **`[题目漏列参会人]`** 是题目-转写称谓不匹配的特殊选项（详见上一节），触发新增参会人

老板回复一次（一条多行消息或一次 batch 选择）→ 完成所有归一。

### ⚠️ 题目-转写称谓一致性检查（强约束，先做这一步再做归一）

转写中常出现暗示**性别 / 婚姻 / 师承 / 上下级关系**的称谓——例如：

| 称谓 | 暗示 |
|-----|------|
| 师姐 / 师妹 | 女性 + 师承关系 |
| 师兄 / 师弟 | 男性 + 师承关系 |
| 老板娘 / 你的夫人 / 你的太太 | 女性 + 与某男性是夫妻 |
| 老板 / 老公 / 你的先生 | 男性 + 与某女性是夫妻 |
| 老朱 / 朱总 | 姓朱的中年男性 |
| 浪子 / 兄弟 | 几乎都是男性 |
| 老大 / 大姐 / 大哥 | 含明确长幼性别信号 |
| 带娃 / 给你带娃 | 暗示对方是孩子的家长（通常配偶） |

**关键规则**：当这种称谓出现时，**先与会议题目里的参会人列表做一致性检查**，再做归一。

#### 检查流程

1. **扫描转写**抽出所有暗示性称谓（"师姐"、"你的夫人"、"老板娘"等）
2. **看题目**列出的参会人是否能匹配上：
   - 例：题目里有 3 个名字 A、B、C
   - 称谓"师姐"暗示女性
   - A、B、C 已被识别为全部男性 → **称谓与题目不匹配**
3. **不匹配时的处理**：
   - **不要**把称谓硬塞给 A/B/C 任意一个
   - **必须问用户**（按当前 runtime 的提问机制——Claude Code 用 AskUserQuestion；Hermes 直接 print；其他 LLM 看 wrapper）："转写中出现『{称谓}』，但题目列出的 {A、B、C} 无匹配——这位是题目漏列的第 4 位参与人，还是某种戏称（如越影管展沅叫师姐）？"
   - 用户回答后再决定：(a) 新增该参会人到图谱；(b) 把称谓注入某具名人物的别名字段；(c) 不入图谱（戏称）

#### 反例（之前犯过的错）

会议题目「（越影、展沅、大富）」三人都是男性。
转写出现「师姐 / 你的夫人 / 老板娘」等女性称谓 5+ 次。
**错误处理**：把"师姐"硬塞给展沅 → 把展沅误判为"大富的妻子" → 全部决策的责任主体写错。
**正确处理**：识别题目-转写不匹配 → AskUserQuestion → 用户答"题目漏列了大富的妻子李潇" → 新增李潇为第 4 参会人。

#### 与「不归一的情况」三条规则的优先级

题目-转写称谓一致性检查 **优先级最高**——先做这一步，**再**做发言人 N 归一、跨会议归一、同人合并。先检查整体参会人花名册的完整性，再做细粒度归一。

### 自动归一备注的格式

最终输出末尾追加：

```markdown
---

**🔧 自动归一备注**（请复核）：
- 转写中 `发言人 X` → 已归一为 `{某人 A}`（依据：上下文 + 别名命中）
- 转写中 `发言人 Y` → 已归一为 `{某人 B}`（依据：自称「我是 {某人 B}」）
- 转写中 `{某新名}` → 新建为新人物（理由：图谱无匹配；如需合并到现有 `{相似某人}` 请手动调整 `people-graph.md`）
```

## 5. 关键词抽取（纪要顶部）

6–8 个为佳，按以下分配：

- 1–2 个**主体业务**（产品 / 服务 / 业务方向）
- 1–2 个**方法/工具**（具体的方法论或技术栈）
- 1–2 个**组织/人才**（组织设计 / 人员部署）
- 1–2 个**行业/趋势**（外部环境 / 行业动态）

**避免**：
- 太宽的词（如「业务」「发展」）
- 太窄的词（具体公司名、具体产品代号）—— 除非这就是会议主题
- 重复同义词

## 6. 章节划分（纪要）

5 节左右最佳。常用聚类模式：

### 模式 A：业务主导
1. 业务现状 / 团队背景
2. 战略调整 / 关键决策
3. 组织 / 人才 / 跨区域
4. 技术应用 / AI 落地
5. 行业趋势 / 外部观察

### 模式 B：项目验收
1. 系统演示 / 功能展示
2. 应用场景规划
3. 竞品对比
4. 技术路径与集成
5. 流程优化建议

### 模式 C：复盘 / 深度长谈
1. 社交反思 / 人际博弈
2. 资源理解 / 眼界提升
3. 项目布局 / 业务进展
4. 心智觉醒 / 自我打磨
5. 生活管理 / 行程安排

按对话主题聚类排，**不按时间顺序排**。

## 7. 转写头部元数据自动抽取（Step 4.2 用）

**目标**：把"老板每次手填日期/地点/类型"压到 0 次。skill 在 Step 4 主动尝试抽取，失败才进 batch 问。

### 7.1 日期抽取

**扫描范围**：转写前 200 行 + 文件名（如 `meeting-2026-05-08.txt`）。

**识别格式**（按优先级）：

| 优先级 | 格式 | 示例 |
|-------|------|------|
| 1 | ISO 标准 | `2026-05-08`、`2026-05-08T09:30` |
| 2 | 斜杠分隔 | `2026/05/08`、`2026/5/8` |
| 3 | 中文 | `2026年5月8日`、`2026 年 5 月 8 日` |
| 4 | 点号分隔 | `2026.05.08`、`2026.5.8` |
| 5 | 时间戳前缀里的日期部分 | `[2026-05-08 09:30:01] 西鸣 …` |
| 6 | 文件名 | `meeting-2026-05-08.txt` → `2026-05-08` |

**冲突处理**：

- 如果转写头部出现的日期 ≠ 文件名日期 → 用**转写头部**（更可信），但记入 4.4 batch 让老板复核
- 如果转写中跨日（早 9 点开到晚 6 点） → 用**最早出现**的日期作为会议日期
- 全失败 → 用 `today` 兜底，**强制**记入 4.4 batch（不能沉默兜底）

### 7.2 地点抽取

**关键词扫描**前 200 行 + 转写最后 50 行（结束语常含"散会"上下文）：

- "今天我们在 X 开会" / "在 X 这边" / "这场会在 X" → X 即地点
- "X 会议室" / "X 办公室" / "X 楼" → 提取 X
- "{城市名}{常见地点后缀}" 如"北京国贸办公室"、"上海徐汇会议室"

**地点歧义**（如同一家公司多个会议室都被提到）→ 取**出现频次最高**的；并列时进 4.4 batch。

**全失败** → 留空字符串（不要兜底为"线上"或"未知"——这是默认行为）。

### 7.3 会议类型自动归类（8 类）

按转写主题词归类，每类的特征关键词：

| 类型 | 特征关键词（出现 ≥3 次任一） |
|------|----------------------------|
| 项目验收 | "demo"、"演示"、"验收"、"测试结果"、"上线"、产品代号 |
| 战略复盘 | "战略"、"方向"、"未来"、"3 年"、"5 年"、"路径" |
| 个人复盘 | "我自己"、"我反思"、"我最近"、"心智"、"焦虑"、"压力" |
| 家庭复盘 | "家里"、"老婆"、"孩子"、"父母"、"家庭" |
| 资源对接 | "认识"、"介绍"、"资源"、"对接"、"投资"、"合作" |
| 同业拆解 | "竞品"、"同行"、"对比"、"他们怎么做的"、对手公司名 |
| 嘉宾分享 | "今天请到"、"分享一下"、"行业洞察"、嘉宾自报家门 |
| 其他 | 上述都不命中 |

**置信度计算**：命中关键词数 / 转写长度归一化。**置信度 ≥0.7** 自动归类；**<0.7** 进 4.4 batch 让老板选。

### 7.4 兜底原则

任何抽取失败的字段，**不要沉默兜底**——记入 4.4 的 batch 询问列表。让老板**显式确认**默认值，避免后续基于错误元数据生成纪要 / 长图。

如果连 batch 都没法发起（hermes 无人值守等场景），**才**用兜底值（today / 留空 / "其他"），并在纪要顶部斜体标注"⚠️ 元数据为兜底值，请老板下次跑会议时复核"。
