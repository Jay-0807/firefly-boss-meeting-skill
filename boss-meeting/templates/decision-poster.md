# 决策长图 模板

## 用法

这是渲染管线的输入：纯 markdown，外部工具会把它转成老板会议长图风格的格式化长图（.jpg）。
推荐渲染管线见 [../references/rendering-pipeline.md](../references/rendering-pipeline.md)。

**模板设计原则——保持 section 顺序，放开 section 内部结构**：

- ✅ **顺序锁死**：开场气泡 → 外部决策 → (推荐) 交锋回顾 → 犀利视角 → 破局方案 → 待办 → 收尾气泡 → 品牌底栏
- ✅ **section 名称随议题适配**：标题随会议主题改写（参见下方"section 名称参考")
- ✅ **section 内部结构灵活**：bullet / 数字编号 / 卡片标签 / 段落 / 流程图 都可以，按议题选最合适的
- ✅ **盲点条数灵活**：通常 2–4 条
- ❌ **不要锁死强制 emoji 标题**

## 完整骨架

```markdown

> {老板称呼}，{开场气泡：第二人称切入，铺垫本次会议的背景钩子。2–4 句、80–150 字。要带视角，不是流水账。**最佳套式：时间锚点 + type label（"这不仅是 X，更是 Y"）+ 自我定位 + 价值预告**。详见 voice-guide。}
```

## section 名称参考（按议题适配）

按会议议题改写命名。下面给 5 类常见议题的命名灵感：

| 会议类型 | 外部决策 | 犀利视角 | 破局方案 | 待办 |
|---------|---------|---------|---------|------|
| 项目验收 | 外部决策结果 | 我的客观看法：你忽略的致命卡点 | "{产品代号}"落地推演方案 | 待办事项（你的"执行账本"）|
| 战略复盘 | 外部核心思考与决策 | 我的犀利看法：你的致命Bug | 高阶资源博弈与自我修补方案 | 执行清单 |
| 个人复盘 | 外部核心决策结果 | 我的客观看法 | 转型"{角色}"进阶方案 | 行动清单（TO-DO）|
| 家庭/复盘 | 外部核心决策结论 | 我的客观看法（犀利视角）| 深度破局方案：建立"{X}心智防火墙" | 待办事项清单 |
| 资源对接 | 外部决策结果 | 我的客观看法：你的盲点 | 落地推演方案 | 待办事项 |

## 副标题怎么写

副标题位置：**H1 标题之后的第一段普通文本**（不加 `>`、不加 `*斜体*`、不加 `**加粗**`）。这是 markdown-to-image 类渲染管线识别副标题的标准方式——它把 `<h1>` 后的第一个 `<p>` 标签自动样式为副标题。

格式要求：
- 10–25 字
- 至少含一个动词（验收 / 推进 / 复盘 / 重塑 / 化解…），节奏密
- 暗示矛盾或决策点
- **不重复主标题信息**

## 待办格式细化

每条待办都要包含：

1. **主题**（一句话动作）
2. **描述**：1–2 行，写明前置条件、判定标准、避免的坑
3. **负责人**：姓名 / 多人并列 / `发言人 N（角色）`（当未确认归一时）
4. **处理时间**：明确日期 / 时间窗

如果是「老板自己执行」，负责人写老板姓名。如果是「等某人回话再做」，处理时间写 `(待 X 回话后)` 而非空着。如果归一不确定，**允许**写 `发言人 N（角色注）` 占位。

**三要素任缺其一，标 `(待补)`**——不要伪装齐全。

## 敏感字段标记规则（与本地渲染配套）

**渲染前提**：决策长图**只能本地渲染**，不能贴到 readpo.com 等在线服务（详见 [../references/rendering-pipeline.md](../references/rendering-pipeline.md) 的"首要原则"）。

即便如此，在生成 markdown 时，skill **保留所有真实信息**（不做不可逆脱敏），便于本地渲染后老板自己回看。但要让"哪些字段是敏感的"对老板和后续脱敏脚本都一目了然——下面是默认标记口径：

### 默认保留 + 一眼可识别

| 字段类型 | 例子 | 处理 |
|---------|------|------|
| 老板姓名 / 称呼 | `张总`、`{老板}` | 保留原文（开场/收尾气泡核心钩子）|
| 其他参会人姓名 | `文轩`、`西鸣` | 保留原文 |
| 公司名 / 产品代号 / 项目代号 | `X-1`、`{公司} 并购案` | 保留原文 |
| 财务数字 | `本季度营收 1200 万`、`让利 15%` | 保留原文 |
| 转写原文片段（犀利视角的引用） | `> 引用转写：「我觉得不需要……」（来源：张总）` | 保留原文 |
| 个人隐私 / 健康 / 家庭 | 偶发但敏感 | 保留原文，但**警示提示老板自查** |

### 可选：脱敏前置宏（默认关闭）

如果老板想要"渲染前自动脱敏"，可在调用 boss-meeting 时传 `redact_for_render=true` 参数，skill 在长图末尾追加一段脱敏后的"分享版 markdown"：

- 真实姓名 → `{角色 1}`、`{角色 2}`
- 财务数字 → `{XX 万}`、`{XX%}`
- 项目代号 → `{项目 A}`

**⚠️ 当前版本暂未实现 `redact_for_render`**——这是占位约定，后续如确认需要再加（参见 plan 文件 P0-3 团队版长图）。在那之前，老板**自己肉眼复核** + **本地渲染** = 最简单可靠的脱敏路径。

### 渲染前自查清单（写在 SKILL.md Step 8 的提示里）

老板拿到 markdown 后，渲染前花 30 秒扫一眼：
- [ ] 这场会议的内容是否方便外发？（即使只发给团队也算外发）
- [ ] 财务数字 / 客户名 / 内部矛盾 是否需要脱敏？
- [ ] 渲染工具确认是本地（`node render.js …` 或 Pandoc），不是 readpo.com？

**任一项不通过，先脱敏再渲染**。
