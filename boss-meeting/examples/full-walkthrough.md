# 端到端流程演示（虚构例子）

> ⚠️ 本示例使用**虚构的会议、虚构的人物、虚构的产品**。仅用于演示 skill 的输入→输出流程与 5 件套 L3 写回方式。**不要把这里的具体内容当作真实方法论指引**——真实生成时按转写实情写。

## 虚构设定

- **老板**：A 总（虚构）
- **公司**：A 集团（虚构，做某类消费品）
- **主要合伙人**：B（产品负责人）、C（运营负责人）
- **本次会议**：A 总与 B、C 讨论一个虚构产品 demo（代号"X-1"）的验收
- **虚构日期**：2026-04-21

## Step 1：输入转写


## Step 2：加载 L3（按需）

skill 扫转写关键词：`X-1` / `生态集成` / `竞品 Y` / `SOP` / `人工标注` / `单界面`。

按 SKILL.md Step 2 的命中规则筛 5 个 L3 文件，**只载入命中的条目**。假设这是第一次跑 X-1 会议，5 个 L3 文件都基本为空——skill 进入"首批入库"模式。

## Step 3：抽取发言人

发言人列表：`A总`、`发言人2`、`发言人3`

初步归一推断：
- `A总` → 与 `boss_name` 参数（用户传入 = "A总"）匹配 → 锁定为本场老板
- `发言人2` → 不确定，从转写"我之前在 Y 那边带过两年"推测可能是新加入主管，AskUserQuestion 问
- `发言人3` → A 总末尾直接称呼"C"，自动归一到 `C`

## Step 4：AskUserQuestion 一次性问

```
Q1: 会议日期？
Q2: 会议地点？
Q3: 会议类型？
Q4: 发言人2 是谁？候选：[新人物（请简述身份）/ 忽略]
```

假设用户回答：
- 日期：2026-04-21
- 地点：A 集团办公室
- 类型：项目验收
- 发言人2：新人物（D，新加入的某主管，竞品 Y 出身）

## Step 5：生成会议纪要 markdown

```markdown
# 会议纪要：X-1 demo 进度对齐与生态集成决议

**会议时间：** 2026年04月21日 14:02 - 14:07
**核心关键词：** X-1、生态集成、竞品 Y 对标、人工标注 SOP、伪效率、单界面集成

---

### 一、demo 进度与功能验收
*   **首版完成情况：** B 负责的 X-1 demo 第一版在 4 月 20 日跑通，整体效果可用。
*   **响应表现：** 当前 demo 响应延迟与竞品 Y 基本持平。

### 二、竞品对标与界面整合
*   **竞品 Y 核心优势：** 生态集成已完成，用户在单界面完成全部操作流程，无需切窗。
*   **本方差距：** 当前需在主工作台与外部系统之间切换，单日切换 1500 次。
*   **决议：** 必须做生态集成，由 D 牵头。

### 三、人工标注 SOP
*   **风险识别：** 人工标注若无规范流程，模型学习方向可能偏离。
*   **决议：** C 牵头制定人工标注 SOP，下周一前提交草案。

---

*本次会议确认了 X-1 demo 的下一阶段重点是生态界面整合与人工标注规范化。*
```

## Step 6：生成决策长图 markdown

```markdown
# X-1 demo 进度对齐与生态集成决议

验收 X-1 demo 首版，被新加入的 D 当场指出生态集成的伪效率盲点。

> A 总，刚听完你们这场 5 分钟的对齐会。我必须当场拍醒你：你今天差点又一次锁死在「学习能力强就够了」的乐观陷阱里——还好 D 把你拽住了。**这不仅是一次 demo 验收，更是一次对你"伪效率盲区"的当场拍醒。**这场会真正的价值，在于你被指出问题后那个「那行吧」的转折。

## 🧠 外部决策结果：必须做生态集成

**核心结论：** 响应延迟与 Y 持平，但伪效率被 Y 吊打——单日 1500 次切窗就是真实人效的护城河。

- 🎯 **战略定位**：不是学习能力对决，是**界面体验对决**。
- 🚪 **界面跃迁**：从"主工作台 + 外部系统"双窗口 → 统一界面。
- ⚡ **落地节奏**：D 牵头走集成方案，B 接 API。
- 🛡 **SOP 兜底**：C 下周一前给人工标注 SOP 草案。

## 🎯 我的客观看法：你的致命Bug

A 总，你这次承认错误的速度比我预期快，这是好事。但有 2 条盲点你必须当场认领。

1. **致命的傲慢——你差点又一次轻视"伪效率"**

   > 引用转写：「切窗这事我觉得不重要，反正用户都是要切来切去的，对吧？」（来源：A 总）

   这是典型的**自我合理化盲区**。你用「反正大家都」把一个会让你**每天浪费 1500 次注意力切换**的真问题轻飘飘合理化掉了。**真实的人效从来不在"响应快"里，在那 1500 次切窗里**。

2. **未引"长记忆关联"**

   本次因 L3 图谱里没有 A 总的相关历史观点，按 voice-guide "图谱里没相关回声不要硬凑" 的反模式禁令，**不写第 3 条长记忆关联**。
```

## 注意

这个示例是**虚构压缩版**。真实场景下：

- 转写浓度：1 小时会议 5000–10000 字（这里仅 800 字）
- 纪要章节：通常 4–6 节
- 犀利视角：2–4 条
- 待办：3–6 条
- 图谱回声：跑过几次会议后「长记忆关联」会越来越频繁

但**模板结构和 L3 写回方式应保持完全一致**。
