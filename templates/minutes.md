# 会议纪要 模板

## 用法

按下面骨架填充。**中性客观，事实导向，不出现第二人称，不评判**。

## 骨架

```markdown
# 会议纪要：{主标题}

**会议时间：** YYYY年MM月DD日 HH:MM - HH:MM
**核心关键词：** {kw1}、{kw2}、{kw3}、{kw4}、{kw5}、{kw6}

---

### 一、{章节主题}
*   **{要点名}：** {描述，2–4 行长度，可以包含数字、人名、决议}
*   **{要点名}：** {描述}
*   **{要点名}：** {描述}

### 二、{章节主题}
*   **{要点名}：** {描述}
*   **{要点名}：**
    *   {子项 1}
    *   {子项 2}
    *   {子项 3}

### 三、{章节主题}
*   **{要点名}：** {描述}
*   **{要点名}：** {描述}

### 四、{章节主题}
*   **{要点名}：** {描述}
*   **{要点名}：** {描述}

### 五、{章节主题}
*   **{要点名}：** {描述}
*   **{要点名}：** {描述}

---

*{结尾一句话总结：本次会议明确了…，重点在于…。}*
```

## 标题级别约定

- 顶级标题：`#`（一级）
- 章节标题：`###`（三级）
- bullet：`*   **要点：** 描述`（星号 + 三空格 + 加粗冒号）

## 主标题命名规则

格式：**核心议题动作 + （关键人物或场景）**

要点：
- 长度 8–18 字
- 至少含一个动词（如：复盘、推演、落地、重塑、对齐、验收、研讨、博弈、激活）
- 体现「这场会议解决/讨论了什么」，**不是泛泛主题**
- 关键人物或场景用小括号附在末尾，如：`（{合作方/嘉宾名}）`、`（{家庭/复盘}）`、`（{产品代号}）`

避免：
- 流水账式（如：`关于 X 的讨论`）
- 形容词堆砌（如：`深度的、全面的、系统的 X`）
- 缺动词（如：`X 与 Y` 没说怎么样）

## 章节划分启发式

5 节左右最佳，3–7 节都可接受。**按主题聚类排，不按时间顺序排**。

常见模式：

- **业务主导**：业务现状 → 战略调整 → 组织/人才 → 技术应用 → 行业趋势
- **项目验收**：系统演示 → 应用规划 → 竞品对比 → 集成路径 → 流程建议
- **复盘/长谈**：核心议题反思 → 资源/眼界提升 → 项目布局 → 自我打磨 → 行程/管理

不必死套，按议题真实结构组织。

## 决策提取的硬规则

只把符合下面任一条件的内容写成「决议/计划」：

- 出现承诺性话术：「我们决定 / 接下来要 / 计划在 X 之前完成 / 下周开始」
- 有明确责任人或时间窗
- 是会议中**明确收敛后**的结论，不是讨论中的发散观点

讨论中提到但未收敛的观点，归类到对应章节作为「讨论要点」，不要伪装成决议。

## 关键词抽取规则

「核心关键词」 6–8 个为佳，按以下分配：

- 1–2 个**主体业务**（产品 / 服务 / 业务方向）
- 1–2 个**方法/工具**（具体的方法论或技术栈）
- 1–2 个**组织/人才**（组织设计 / 人员部署）
- 1–2 个**行业/趋势**（外部环境 / 行业动态）

**避免**：
- 太宽的词（如「业务」「发展」）
- 太窄的词（如具体公司名、具体产品代号）—— 除非这就是会议主题
- 重复同义词

## 结尾一句话总结

格式：`*本次会议{动词1}了…，{动词2}…。*`

要点：
- 用斜体
- 一两句，不超过 50 字
- 写「本次会议干成了什么」+「下一步重心是什么」
- 不写「本次会议讨论了 X、Y、Z」（流水账）

## 与决策长图的内容差异

| 维度 | 会议纪要 | 决策长图 |
|------|---------|---------|
| 受众 | 团队 / 外部 | 老板本人 |
| 语气 | 中性客观 | 第二人称、犀利 |
| 视角 | 事实陈述 | 诊断 + 提醒 |
| 内容 | 完整覆盖会议要点 | 只抓决策 + 盲点 + 待办 |
| 评判 | 无 | 必有 |

**同一场会议，纪要和长图各写一份，互不复用内容**——纪要可以从长图剥离客观事实重写，但长图的犀利视角段不应直接搬进纪要。
